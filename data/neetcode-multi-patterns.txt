Multi-pattern problems — grouped by WHY they have multiple tags
================================================================

Every problem here has 2+ truePatterns because the NeetCode solution article
lists multiple approaches that share the best time/space. This file groups
them by the *reason* that happened — not by which pattern names appear.

102 problems.


########################################################################
# Why: one scan, two ways to describe it
# (6 problems)
########################################################################

These are multi-tagged because the optimal solution is basically a single O(n) pass,
but NeetCode's article presents that pass under two names — e.g. "Two Pointers" and
"Dynamic Programming", or "Kadane" and "Prefix & Suffix", or "Sliding Window" and
"Iteration".

Nothing about the complexity forces two patterns. The article just frames the same
work two ways, and our retagger mapped each frame to a different pattern slug.

For curriculum: pick the framing you want to practice. Do not treat these as two
separate techniques you must learn independently for this problem.

# Why: same algorithm, different bookkeeping structure
# (13 problems)
########################################################################

These are multi-tagged because the core algorithm is identical (usually backtracking
or a stack-based design). What changes between "optimal" approaches is only how you
store auxiliary state — hash set vs boolean array vs bitmask, stack vs doubly linked
list, hash set vs bitmask on a prefix, etc.

Those bookkeeping choices got mapped to different pattern tags (backtracking +
arrays-hashing + bit-manipulation, or stack + linked-list), even though you are not
learning two problem patterns — you are learning one pattern with interchangeable
data structures.

For curriculum: tag the algorithm (backtracking / stack). Ignore the storage variant
as a separate pattern.
